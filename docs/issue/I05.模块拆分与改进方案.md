# 模块拆分与改进方案

## 1. 背景与目标

当前仓库里三块逻辑已经初具雏形，但职责边界不够清晰：

- **提示词**散落在 `domain/commit-message/prompts.ts`、`domain/file-review/prompts.ts`，且每个文件都把"静态提示词文本"和"运行时消息构造（wrapDiff / wrapNewFile 等）"混写在一起。
- **文件 diff** 全部堆在 `infra/git/diff.ts`：它既提取 diff 文本、又过滤二进制、还顺手做"新增文件检测 / 文件统计 / 是否有变更"等**文件变更**判断。
- **文件变更**（哪些文件变了、怎么变的）没有一等公民模型，相关函数散落在 diff.ts 各处，被 `gate.ts`、`commit.ts` 各自取用。

目标：把 **提示词管理模块 / 文件变更模块 / 文件 diff 模块** 拆成三个职责单一、可独立测试、可独立演化的模块，并借机落地 `I04` 提出的 DRY 改进（共享 `COMMIT_FORMAT_RULES`、`COMMIT_SAFETY`）。

## 2. 现状（as-is）

```
src/domain/commit-message/prompts.ts   # 提示词文本 + wrapDiff/wrapPartialDiff/wrapDraft/...（混合）
src/domain/file-review/prompts.ts       # REVIEW 提示词文本 + wrapNewFile/wrapNewFiles/repairHint（混合）
src/domain/shared/language.ts           # LANGUAGE_RULES（共享，好）
src/infra/git/diff.ts                   # getStagedDiff / getStagedFileStats / getNewFileContents / hasStagedChanges / hasChangesToStage（混合）
src/domain/commit-message/split.ts      # parseDiffBlocks / collapseLargeBlocks / groupIntoBatches（实为 diff 处理，却放在 domain）
src/domain/commit-message/{generator,batch,checker}.ts
src/domain/file-review/{reviewer,gate}.ts
```

主要痛点：

1. **提示词文本 ↔ 消息构造混写**：改措辞的人要读懂 `wrapXxx` 函数，改构造的人又被长提示词淹没。
2. **diff ↔ change 概念混淆**：`diff.ts` 本应只管"文本差异"，却承担了"变更采集"。新增/删除/重命名/二进制这类**变更语义**没有模型承载。
3. **共享片段仍重复**：`I04` 指出的格式规则三处重复、注入防御散落（P1/P2）尚未解决，根因就是没有统一的提示词模块来承载"共享块"。
4. **消息组装样板重复**：`generator.ts` / `batch.ts` / `reviewer.ts` 各自手写 `[{role:'system',...},{role:'user',...}]`。

## 3. 目标架构（to-be）

```
src/

│   ├── blocks/                      # 单一信息源的可复用片段（落地 I04 的 P1/P2）
```

## 4. 模块一：提示词管理模块

**职责**：集中存放所有 LLM 提示词文本与消息构造，对外暴露"组装好的消息"，消除重复样板与重复片段。

```ts
// src/prompts/types.ts
import type OpenAI from "openai";
export type ChatMsg = OpenAI.ChatCompletionMessageParam;

export interface PromptDefinition {
  id: string;
  system: string;                          // 已组合的 system prompt
  buildUser?: (data: unknown) => string;   // 包裹不可信数据，构造 user 消息
  repairHint?: (reason: string) => string; // 校验失败时的修复提示
}

/** 统一消息组装：消除 generator/batch/reviewer 里的手写样板 */
export function buildMessages(p: PromptDefinition, data?: unknown): ChatMsg[] {
  const msgs: ChatMsg[] = [{ role: "system", content: p.system }];
  if (p.buildUser) msgs.push({ role: "user", content: p.buildUser(data) });
  return msgs;
}
```

**共享块（落地 I04 的 P1/P2）**：`blocks/format.ts` 导出 `COMMIT_FORMAT_RULES`，`blocks/safety.ts` 导出 `COMMIT_SAFETY`（独立 `<safety>` 节）。三套提交提示词在 `<rules>` 开头统一引用，注入防御不再散落各 `context`。

```ts
// src/prompts/commit-message/system.ts（示意）
export const SYSTEM_PROMPT = `${COMMIT_ROLE}
<context>...</context>
${COMMIT_SAFETY}
<task>...</task>
${LANGUAGE_RULES}
${COMMIT_TYPES}
<rules>
${COMMIT_FORMAT_RULES}
6. ${TYPE_SELECTION}
... 其余独有规则
</rules>
<examples>...</examples>
<output>...</output>`;
```

**调用侧简化**（以 generator 为例）：

```ts
// 之前
const messages = [
  { role: "system", content: SYSTEM_PROMPT },
  { role: "user", content: wrapDiff(diff) },
];
// 之后
const messages = buildMessages(commitMessagePrompt, diff); // buildUser = wrapDiff
```

**收益**：提示词文本与构造分离；共享片段真正单一来源；消息组装一处实现；后续可加"提示词单测"（断言共享块被引用、XML 分节完整、无重复规则）。

## 5. 模块二：文件变更模块

**职责**：建模并采集"哪些文件变了、怎么变的"，作为一等公民，与"文本 diff"解耦。

```ts
// src/infra/git/changes.ts
export type ChangeStatus = "added" | "modified" | "deleted" | "renamed" | "copied";

export interface FileChange {
  path: string;
  status: ChangeStatus;
  isBinary: boolean;
  additions: number;
  deletions: number;
}

export interface ChangeSet {
  files: FileChange[];
  newFiles: FileChange[];                 // status === "added"
  binaryFiles: FileChange[];             // isBinary === true
  hasStagedChanges: boolean;
  hasChangesToStage: boolean;             // 是否有需 git add 的未暂存变更
}

export function getStagedChangeSet(): ChangeSet { /* 用 --numstat / --name-status 聚合 */ }
```

把现有 `getStagedNewFiles / getNewFileContents / getStagedFileStats / hasStagedChanges / hasChangesToStage` 迁入本模块。`gate.ts` 改为 `reviewNewFiles(changeSet.newFiles, config)`，`commit.ts` 用 `changeSet.hasStagedChanges / hasChangesToStage` 判断流程。

## 6. 模块三：文件 diff 模块

**职责**：只管"文本差异的提取与加工"——原始 diff、二进制过滤、超大块折叠、分块。把 `domain/commit-message/split.ts` 迁回此处（它本就是 diff 处理，不该留在 domain）。

```ts
// src/infra/git/diff/extract.ts
export function getStagedDiffRaw(): string;            // 纯 git diff --cached

// src/infra/git/diff/process.ts
export interface ProcessedDiff {
  text: string;            // 已过滤二进制内容、已追加「=== 二进制文件变更（仅显示文件名）===」段
  binaryFiles: string[];
}
export function processDiff(raw: string): ProcessedDiff;   // 保留现有二进制排除技巧

// src/infra/git/diff/split.ts（从 domain 迁入）
export { parseDiffBlocks, collapseLargeBlocks, groupIntoBatches };
```

`commit.ts` 流程变为：`raw = getStagedDiffRaw()` → `processed = processDiff(raw)` → `generateCommitMessageBatched(processed.text, config)`。原 `getStagedDiff()` 的二进制段落逻辑整体搬进 `processDiff`。

## 7. 三模块协作

```
commit.ts
  ├─ changes.getStagedChangeSet()  ──► ChangeSet
  │     └─ gate.runReviewGate(changeSet.newFiles)         （文件变更模块）
  ├─ diff.extract.getStagedDiffRaw() → diff.process.processDiff() → ProcessedDiff
  │                                                      （文件 diff 模块）
  └─ batch.generateCommitMessageBatched(processed.text)
        └─ prompts.buildMessages(commitMessagePrompt, diff)  （提示词模块）
              ├─ system 由 blocks/* 组合（含 I04 的 format/safety）
              └─ buildUser = wrapDiff
```

边界清晰：**变更模块给"是什么文件"**，**diff 模块给"差异文本"**，**提示词模块消费两者拼出 LLM 输入**。

## 8. 改进方案对比

| 方案 | 说明 | 收益 | 成本/风险 |
| --- | --- | --- | --- |
| **A（推荐）** | 仅做逻辑分层 + 共享块；提示词仍内联 TS，不动运行方式 | 消除混写与重复，落实 I04，风险最低 | 需移动/重命名若干文件 |
| **B** | 在 A 基础上把提示词外部化为 `.prompt.md` 模板，运行时加载 | 非开发者也能改措辞，便于 A/B | 增加加载层、缓存与测试负担 |
| **C** | 在 A/B 基础上让 diff/change 输出强类型直接驱动提示词构造，减少字符串拼接 | 类型安全、少出错 | 改动面大，需同步改 checker 校验 |

建议先落地 **A**（与 `I04` 的 P1→P2 顺序一致），B/C 视后续需要再叠加。

## 9. 落地路线（分阶段）

1. **P0 建骨架**：新增 `src/prompts/{types,index}.ts` 与 `buildMessages`；把 `LANGUAGE_RULES` 迁入 `prompts/blocks/language.ts` 并 re-export。
2. **P1 抽共享块（对应 I04）**：新增 `blocks/{role,types,format,safety,output}.ts`，三套提交提示词改为由块组合；`file-review` 也引用 `safety` 块。
3. **P2 拆提示词与构造**：`prompts/commit-message/{system,partial,merge,wrappers}.ts` + `prompts/file-review/{system,wrappers}.ts`；`generator/batch/reviewer` 改用 `buildMessages`。
4. **P3 拆文件 diff**：`infra/git/diff/{extract,process,split}.ts`，迁入 `split.ts` 与 `getStagedDiff` 逻辑。
5. **P4 拆文件变更**：`infra/git/changes.ts` 建模 `ChangeSet`，迁入相关函数；`gate.ts`/`commit.ts` 改用 `ChangeSet`。
6. **P5 收尾**：`tsc --noEmit`、`eslint`、跑一次真实提交验证；补提示词单测（可选）。

## 10. 风险与注意

- 移动 `split.ts` 时注意它导出被 `batch.ts` 引用，需同步改 import 路径。
- `process.ts` 必须保留现有"排除二进制文件再 diff"的技巧，否则大二进制会撑爆上下文。
- `ChangeSet` 的 `newFiles` 内容读取（含二进制占位）逻辑从 `getNewFileContents` 平滑迁移，行为不变。
- 若选方案 B，提示词文件建议放进 `src/prompts/*.prompt.md` 并随构建拷贝，避免运行时路径问题。
