# 模块职责划分（整体架构重构）

## 0. 需求原文

> 请对当前项目做一次整体性重构，从架构层面将其拆分为职责清晰、边界明确的模块结构。具体要求：
> 1）按业务/功能领域划分模块，每个模块职责单一，对外暴露清晰的接口，模块间依赖方向明确，避免循环依赖；
> 2）将通用能力（配置、日志、错误处理、数据访问等）抽取到独立的公共层；
> 3）消除重复代码与过度耦合的胶水逻辑。
> 请先简要说明现有结构的主要问题，并给出拟采用的分层与模块划分方案（含目录结构示意），再按该方案实施改动。
> 重构须保持既有功能与外部行为不变，不新增功能、不更换技术栈，确保改动后项目可正常编译运行，并在最后列出各模块的职责说明与模块间依赖关系。

## 1. 现有结构的主要问题

### P1【严重】领域层反向依赖应用层，存在回边
`src/domain/file-review/gate.ts` 从 `@/app/cli/errors` 引入 `CliError`、从 `@/app/cli/input` 引入 `question`。
形成 **app → domain → app** 的回边；领域逻辑里混入了终端交互（readline 提问）与进程退出码语义，是典型的层违规。

### P2【严重】错误处理定义错位
`CliError`（含 `exitCode`）定义在 `app/cli/errors.ts`，却被领域层抛掷，又被 `app/cli/program.ts` 用于统一退出码处理。错误类型是公共能力，不应隶属于 CLI 目录。

### P3【高】通用能力散落，缺少独立公共层
- 配置：`infra/config/`
- 日志：`utils/logger.ts`
- 时间格式化：`utils/format-time.ts`
- 交互原语：`app/cli/input.ts`

`utils/` 沦为杂物抽屉，四类通用能力分散在三个不同层级，命名与位置都不统一。

### P4【高】提示词文本仍有残留散落（`I05` 未收尾）
- `LANGUAGE_RULES` 实体仍在 `domain/shared/language.ts`，`prompts/blocks/language.ts` 只是 re-export —— 提示词模块反向依赖 domain。
- `commitMessageRepairHint`（重试修复提示，本质是提示词文本）仍与校验逻辑同处 `domain/commit-message/checker.ts`。
- `infra/llm/retry.ts` 内联了一段中文默认修复提示。

### P5【中】基础设施层职责不清，存在重复胶水
- `batch.ts`（领域编排）内联了 token 预算计算（`effectiveLimit`、`FRAMING_OVERHEAD`、`SAFETY_MARGIN_RATIO`），属 LLM 基础设施职责。
- `infra/llm/transport/client.ts` 的 `singleTurn` 自行组装 system+user 消息，与 `prompts.buildMessages` 形成**两套消息组装**。
- `infra/git/diff/split.ts` 依赖 `@/infra/llm/tokens`，让 git 模块横向耦合 LLM 模块。

### P6【中】两个业务域结构不对称
`commit-message` 侧校验已独立为 `checker.ts`；`file-review` 侧的校验器（`reviewValidator`、`REASON_MAX_LENGTH`）却内嵌在 `reviewer.ts`，与 LLM 调用混写。

### P7【低】重复实现交互输入
`infra/config/loader.ts` 内联 `createInterface` 问答，与 `app/cli/input.ts` 的 `question()` 重复。

### P8【低】时间格式化重复
`utils/logger.ts` 内部自带 `formatTime()`，`utils/format-time.ts` 另有 `formatElapsed()`，两份时间格式化胶水。

## 2. 分层方案与依赖方向

```
L4  app       应用层：CLI 注册、命令编排、用户交互步骤
     ↓
L3  domain    领域层：按业务域划分（commit-message / file-review），纯业务编排
     ↓
L2  infra     基础设施层：数据访问与外部系统（git / llm）
     ↓
L1  prompts   提示词资源层：提示词文本与消息构造（叶子模块）
     ↓
L0  config / shared  配置层 / 公共层
```

**依赖规则（只允许自上而下，禁止反向）**

| 层 | 可依赖 | 禁止依赖 |
| --- | --- | --- |
| `app` | `domain`、`prompts`、`infra`、`config`、`shared` | — |
| `domain` | `prompts`、`infra`、`config`、`shared` | `app` |
| `infra` | `config`、`shared` | `domain`、`app` |
| `prompts` | 仅 `openai` 类型 | `domain`、`app`、`infra` |
| `config` | `shared` | 其余全部 |
| `shared` | 无（叶子） | 其余全部 |

> 关键修正：**`domain` 不再依赖 `app`**（P1），**`prompts` 不再依赖 `domain`**（P4）。

## 3. 目录结构示意（to-be）

```
src/
├── shared/                    # L0 公共层
│   ├── errors.ts              # CliError / AppError（含 exitCode）
│   ├── logger.ts              # 分级日志器 createLogger / setLogLevel
│   ├── time.ts                # formatElapsed / formatClockTime
│   ├── input.ts               # question() 终端交互原语
│   └── tokens.ts              # estimateTokens（文本→token 估算，纯启发式）
├── config/                    # L0.5 配置层
│   ├── types.ts               # AppConfig / LLMConfig
│   └── loader.ts              # DEFAULT_CONFIG / loadUserConfig / saveUserConfig / loadConfig
├── prompts/                   # L1 提示词资源层（叶子）
│   ├── types.ts               # PromptDefinition / buildMessages
│   ├── blocks/                # role / commit-types / format / safety / language / output
│   ├── repair.ts              # 通用默认修复提示
│   ├── commit-message/        # system / partial / merge / wrappers / repair
│   ├── file-review/           # system / wrappers
│   └── index.ts
├── infra/                     # L2 基础设施层（数据访问）
│   ├── git/
│   │   ├── runner.ts          # execGit 原语（进程调用）
│   │   ├── repo.ts            # isGitRepo / gitAddAll / gitCommit / gitReset
│   │   ├── changes.ts         # ChangeSet 模型与变更采集
│   │   └── diff/              # process（二进制过滤）/ split（分块）/ index（getStagedDiff）
│   └── llm/
│       ├── budget.ts          # effectiveLimit（token 预算）
│       ├── retry.ts           # callWithValidation（校验重试）
│       └── transport/         # client（chatCompletion）/ response（extractContent）
├── domain/                    # L3 领域层（按业务域）
│   ├── commit-message/        # checker（校验）/ generator（单批）/ batch（分批编排）
│   └── file-review/           # checker（校验）/ reviewer（审查调用）
├── app/                       # L4 应用层
│   ├── cli/program.ts         # 命令注册、日志级别、错误出口
│   ├── steps/review.ts        # 审查门禁（交互上移到应用层）
│   └── commands/              # commit / init
└── index.ts                   # 入口
```

## 4. 各模块职责说明

| 模块 | 层 | 职责 | 对外接口 |
| --- | --- | --- | --- |
| `shared` | L0 | 日志、错误类型、时间格式化、终端输入、token 估算等与业务无关的能力 | `createLogger`/`setLogLevel`、`CliError`、`formatElapsed`/`formatClockTime`、`question`、`estimateTokens` |
| `config` | L0.5 | 配置的默认值、加载、校验收敛与持久化 | `DEFAULT_CONFIG`、`loadConfig`、`loadUserConfig`、`saveUserConfig`、类型 `AppConfig` |
| `prompts` | L1 | 所有提示词文本的单一来源与消息组装；共享块（role/type/format/safety/language/output） | `SYSTEM_PROMPT` 等常量、`buildMessages`、`PromptDefinition`、各 `wrapXxx`、`*RepairHint` |
| `infra/git` | L2 | git 数据访问：命令原语、仓库操作、变更集采集、diff 提取/过滤/分块 | `execGit`、`isGitRepo`/`gitAddAll`/`gitCommit`/`gitReset`、`getStagedChangeSet`/`getNewFileContents`、`getStagedDiff`、`parseDiffBlocks` 等 |
| `infra/llm` | L2 | LLM 数据访问：传输、响应解析、token 预算、校验重试 | `chatCompletion`、`extractContent`、`effectiveLimit`、`callWithValidation` |
| `domain/commit-message` | L3 | 提交信息生成的业务编排：格式校验、单批生成、分批流水线 | `validateCommitMessage`、`generateCommitMessage`、`generateCommitMessageBatched` |
| `domain/file-review` | L3 | 提交前文件审查的业务编排：结果校验、审查调用 | `ReviewResult`、`reviewValidator`、`reviewNewFiles` |
| `app` | L4 | CLI 注册与参数、命令流程编排、用户交互（含审查门禁）与错误出口 | `runCli`、`runCommit`、`runInit`、`runReviewGate` |

## 5. 模块间依赖关系

| 依赖方 → 被依赖方 | 说明 |
| --- | --- |
| `app` → `domain` | 命令编排调用提交信息生成与文件审查 |
| `app` → `infra/git` | 暂存/提交等 git 操作、变更状态判断 |
| `app` → `config` | 加载配置 |
| `app` → `shared` | 日志、错误、交互、时间格式化 |
| `domain` → `prompts` | 取提示词并组装消息 |
| `domain` → `infra/llm` | 发起 LLM 调用与校验重试、token 预算 |
| `domain` → `infra/git` | 分批时做 diff 分块 |
| `domain` → `shared` | 日志、token 估算 |
| `domain` → `config` | 读取 LLM 参数 |
| `infra/llm` → `config`、`shared` | 读取端点/模型参数；日志、token 估算、时间格式化 |
| `infra/git` → `shared` | token 估算（分块）、无其它依赖 |
| `prompts` → `shared` | 无（仅 `openai` 类型；`LANGUAGE_RULES` 已迁入 blocks） |
| `config` → `shared` | 交互原语、日志 |

**无循环依赖**：`shared`/`prompts` 为叶子；`config` 仅依赖 `shared`；`infra` 不依赖 `domain`/`app`；`domain` 不依赖 `app`。

## 6. 实施步骤

1. 新建 `shared/`（errors、logger、time、input、tokens）。
2. 新建 `config/`（types、loader），loader 改用 `shared/input` 的 `question()`。
3. `prompts/` 收尾：`LANGUAGE_RULES` 实体迁入 `blocks/language.ts`；新增 `repair.ts` 与 `commit-message/repair.ts`；删除 `domain/shared/`。
4. `infra/` 细化：新增 `git/repo.ts`、`llm/budget.ts`；删除 `llm/tokens.ts`（并入 shared）、删除 `client.ts` 的 `singleTurn`。
5. `domain/` 对称化：`file-review/checker.ts` 独立；`batch.ts` 改用 `budget` 与 `buildMessages`。
6. `app/` 交互上移：新增 `steps/review.ts`，删除 `domain/file-review/gate.ts`。
7. 全量改 import 路径，删除旧目录（`utils/`、`infra/config/`、`domain/shared/`）。
8. `tsc --noEmit` + `eslint` + 构建验证。

## 7. 行为不变约定

- 不新增功能、不更换技术栈；仅移动文件、拆分职责、改 import 路径。
- 所有 `console.log/warn/error` 的用户可见文案、顺序、措辞保持原样。
- git 命令、LLM 请求参数、校验规则与重试次数保持原样。
- 提示词文本逐字保留（仅做归位与共享块抽取）。
