# 项目结构



架构说明以源码为准。行号对应 `src/` 下的当前实现。



## 1 定位与边界



`grc`（git-repo-comitter）：读取 git 暂存区变更，调用 OpenAI 兼容接口生成符合 Conventional Commits 的中文提交信息，写入 `git commit`。



| 在边界内 | 不在边界内 |

|---|---|

| 变更采集（含二进制识别）、diff 切分与折叠 | 分支管理、push / 远程操作 |

| 提交信息生成、分批合并、格式校验与重试 | 代码改写、格式化、lint |

| 提交前新增文件审查门禁 | LLM 服务自身的部署与鉴权体系 |

| 以库或 CLI 两种方式对外提供上述能力 | git hook 的自动安装与卸载 |



## 2 领域对象



| 对象 | 定义位置 | 说明 |

|---|---|---|

| `AppConfig` | `config/types.ts:14` | 完整运行时配置：`llm` + `apiKey` + `endpoint` |

| `LLMConfig` | `config/types.ts:7` | 模型、温度、输入/输出 token 额度 |

| `UserConfig` | `config/types.ts:24` | 配置文件形状，顶层与 `llm` 内部字段均可缺省 |

| `ChangeSet` | `infra/git/changes.ts:25` | 暂存区变更集：`files` / `newFiles` / `binaryFiles` / 两个布尔量 |

| `FileChange` | `infra/git/changes.ts:17` | 单文件变更：路径、状态、是否二进制、增删行数 |

| `CommitOutcome` | `domain/commit-flow.ts:77` | `CommitSuccess`（已提交）与 `CommitSkipped`（未提交）的可辨识联合 |

| `ReviewResult` | `domain/file-review/checker.ts:9` | 审查结论：是否可提交、可疑文件、原因 |

| `PromptDefinition<TInput>` | `prompts/types.ts:15` | 提示词定义：系统文本 + 可选 user 构造器 + 可选修复提示 |



## 3 关键业务流程：一次提交



编排入口 `executeCommit`（`domain/commit-flow.ts:159`），库与 CLI 共用。



| # | 步骤 | 位置 | 失败/分支 |

|---|---|---|---|

| 1 | 校验 `config.apiKey` | `commit-flow.ts:165` | 抛 `CONFIG_MISSING` |

| 2 | 校验目标路径是 git 仓库 | `commit-flow.ts:177` | 抛 `NOT_GIT_REPO` |

| 3 | 按调用作用域装配进度输出槽 | `commit-flow.ts:187` | 退出时还原（`:224`） |

| 4 | 暂存：`stagedOnly` 则校验已有暂存，否则 `git add` | `commit-flow.ts:101` | 抛 `NO_STAGED_CHANGES` |

| 5 | 审查门禁：仅在传入 `onReview` 且有新增文件时启用 | `commit-flow.ts:124` | 回调返回 false → 抛 `USER_CANCELLED` |

| 6 | 提取暂存 diff（排除二进制） | `commit-flow.ts:194` | 为空 → 返回 `CommitSkipped(NO_CHANGES)` |

| 7 | 生成提交信息（可能分批） | `commit-flow.ts:211` | 校验失败抛 `VALIDATION_FAILED`、空响应抛 `LLM_FAILED` |

| 8 | 执行 `git commit` | `commit-flow.ts:218` | git 报错向上抛 `GIT_FAILED` |

| 9 | 返回 `CommitSuccess`（含 `message` / `batchCount` / `elapsedMs`） | `commit-flow.ts:222` | — |



分批生成（`domain/commit-message/batch.ts:66`）：



| 分支 | 条件 | 位置 |

|---|---|---|

| 直接生成 | `estimateTokens(diff) <= effectiveLimit` | `batch.ts:74` |

| 折叠后生成 | 超大块折叠为文件名占位后仍可容纳 | `batch.ts:80` |

| 分批生成 | 按 `groupIntoBatches` 切批 → 逐批出草稿 → `fitWithinBudget` 挑选 → 合并 | `batch.ts:89`~`:126` |



## 4 分层与依赖规则



```

        ┌─────────────┐   ┌─────────────┐

        │  src/cli.ts │   │ src/lib.ts  │     入口（不属于层）

        │  CLI 启动器 │   │  库公共 API │

        └──────┬──────┘   └──────┬──────┘

               │                 │

        ┌──────▼──────┐          │

        │     app     │          │        终端渲染、命令、交互、退出码

        └──────┬──────┘          │

               │                 │

   ┌───────────▼─────────────────▼───────────┐

   │                 domain                  │  业务编排与校验，唯一业务真相来源

   └───────┬───────────────────┬─────────────┘

           │                   │

   ┌───────▼───────┐   ┌───────▼───────┐

   │     infra     │   │    prompts    │  外部系统访问 / 提示词资源

   └───────┬───────┘   └───────┬───────┘

           │                   │

   ┌───────▼───────────────────▼───────┐

   │              config               │    配置输入（贯穿各层）

   └───────────────┬───────────────────┘

                   │

           ┌───────▼───────┐

           │     shared    │            纯工具，不依赖任何层

           └───────────────┘

```



| 层 | 允许依赖 | 职责 | 禁止 |

|---|---|---|---|

| `app` | `config` `domain` `shared` | 参数解析、终端渲染、交互提问、退出码翻译 | 承载业务编排；被 `domain`/`infra` 依赖 |

| `domain` | `config` `infra` `prompts` `shared` | 业务编排与结果校验 | 打印、提问、读写文件、调用 `process.exit` |

| `infra` | `config` `shared` | git 进程调用、LLM 传输、token 预算 | 依赖 `prompts`；抛 CLI 语义错误 |

| `prompts` | `shared` | 提示词文本与消息组装 | 依赖 `domain`/`infra`/`app` |

| `config` | `shared` | 配置默认值、收敛、文件读写 | 终端交互、直接 `console.*` |

| `shared` | 仅 `shared` | 日志、进度、错误、token 估算、行宽上限 | 依赖任何上层；含终端交互原语 |



实测无例外：全部模块的 `@/` 引用方向均满足上表（2026-10-29 逐文件核对）。

## 6 双入口



| 入口 | 源文件 | 产物 | 消费者 |

|---|---|---|---|

| 库 | `src/lib.ts` | `dist/index.js`（ESM）、`dist/index.cjs`（CJS）、`dist/types/lib.d.ts` | 外部代码（Node） |

| CLI | `src/cli.ts` | `dist/cli.cjs`（带 shebang） | `grc` / `git-repo-comitter` 命令 |

| 浏览器库 | `src/lib-browser.ts` | `dist/browser/index.js`（ESM）、`dist/types/lib-browser.d.ts` | 浏览器 / WebView 经 `git-repo-comitter/browser` 子路径导入 |

两个 Node 入口（`cli.ts` 与 `lib.ts`）在加载时均须调用 `setupNodeGitExecutor()` 装配默认 git 执行器；浏览器入口 `lib-browser.ts` 不装配，由调用方经 `setGitExecutor` 注入（强制约定见 S07 §3 E1）。



库入口是**唯一对外承诺**：只有 `src/lib.ts` 导出的符号属于契约，其余模块可随版本调整。



公共 API 分组：



| 分组 | 符号 |

|---|---|

| 编排 | `commit`（= `executeCommit`）、`CommitRequest` / `CommitOutcome` / `CommitSuccess` / `CommitSkipped` |

| 生成与校验 | `generateCommitMessage`、`generateCommitMessageBatched`、`validateCommitMessage` |

| git | `getStagedDiff`、`gitCommit` |

| 配置 | `resolveConfig`、`loadDefaultConfig`、`loadUserConfigFile`、`AppConfig` / `LLMConfig` / `UserConfig` |

| 横切 | `GrcError` / `GrcErrorCode`、`setLogLevel` / `setLogSink`、`setProgressSink` / `getProgressSink` |



CLI 是库的参考消费者：`app/commands/commit.ts:34` 调用的正是 `executeCommit`，因此两者不存在两套行为。

浏览器入口 `src/lib-browser.ts` 是**纯函数侧子集**：仅导出配置（`resolveConfig` / `loadDefaultConfig`）+ 生成（`generateCommitMessage` / `generateCommitMessageBatched`）+ 校验（`validateCommitMessage`）+ 横切（`GrcError` / 日志 / 进度），不导出任何 git 读写能力（`getStagedDiff` / `gitCommit`）与 Node 文件 IO（`loadUserConfigFile` / `saveUserConfig`），使其 import 图零 Node 内置模块、可在浏览器 / WebView 直接打包（F07）。



## 7 横切机制



| 机制 | 实现 | 库默认行为 |

|---|---|---|

| 错误 | `GrcError(code)`（`shared/errors.ts:28`），`CliError` 供 CLI 定制文案与退出码 | 抛错，不退出进程；`code` 是稳定契约 |

| 进度 | `emitProgress` + 输出槽（`shared/progress.ts:38`），`CommitRequest.onProgress` 按调用装配 | 未装配即静默 |

| 日志 | `createLogger(ns)` 分级（trace~error），`setLogSink` 可接管（`shared/logger.ts:89`） | 默认 info，业务日志多为 debug/trace |

| 配置 | `resolveConfig` 纯函数（`config/loader.ts:86`）；文件读写下沉到 `config/user-file.ts`（`loadUserConfigFile` / `saveUserConfig`），浏览器入口不导入该模块；CLI 的告警与交互修复在 `app/config/load.ts:59` | 不读 `~/.grc`，配置显式传入 |

| 退出码 | 仅 `app/cli/program.ts:38` 的 `handleCliError` 做 `code → 退出码` 翻译（映射表 `:26`） | 不涉及 |

| token 估算 | `estimateTokens`（`shared/tokens.ts:16`）：2 字符/token 折中 | — |

| 行宽上限 | `shared/commit-limits.ts`：标题 78、正文行 118、要点 10 条 | 提示词与校验器共用同一组数字 |

## 9 数据流



```

CLI:   grc [-s] → app/cli/program → app/commands/commit

                                     ├─ 读 ~/.grc/config.json（app/config）

                                     ├─ onProgress = console.log

                                     └─ onReview   = 终端问答

                                          ↓

库:    commit({ config, repoPath, stagedOnly, onProgress, onReview })

                                          ↓

       domain/commit-flow.executeCommit

         ├─ infra/git/repo      isGitRepo / gitAddAll / gitCommit

         ├─ infra/git/changes   getStagedChangeSet / readNewFileContents

         ├─ infra/git/diff      getStagedDiff（切块、折叠、分批）

         ├─ prompts             buildMessages（system + user）

         ├─ infra/llm/transport chatCompletion → extractContent

         ├─ infra/llm/retry     callWithValidation（校验失败附修复提示重试）

         ├─ domain/*/checker    validateCommitMessage / validateReviewResult

         └─ shared/progress     emitProgress（可静默）

                                          ↓

       返回 CommitOutcome（结构化）→ CLI 渲染 或 调用方自行处理

```



## 10 缺陷与风险台账



| 编号 | 级别 | 问题 | 定位 |

|---|---|---|---|

| R1 | 🟠 | 进度槽与日志级别是模块级单例，两个并发 `commit()` 会互相覆盖；`commit-flow.ts:187` 的「装配—还原」仅在串行下成立 | `shared/progress.ts:15`、`shared/logger.ts:30`、`domain/commit-flow.ts:187` |

| R2 | 🟡 | `execFileSync` 未接管 stderr，git 自身报错（如 `fatal: not a git repository`）直接漏到终端，绕开输出槽 | `node/git/child-process-executor.ts:22` |

| R3 | 🟡 | 提示词与校验器共用行宽上限，但 `MAX_BODY_BULLETS` 等数值无回归测试，改提示词易与校验脱节 | `shared/commit-limits.ts`、`prompts/blocks/format.ts` |

| R4 | 🟡 | `estimateTokens` 按字符数折算，中文与代码混合时误差偏大，可能触发不必要的分批 | `shared/tokens.ts:16` |

| R5 | ⚪ | `ValidationResult` 与内部 `ValidationOutcome` 同构但重复声明，需在 `lib.ts` 手工同步 | `src/lib.ts:67` |

| R6 | ⚪ | 全仓 ESLint（jsdoc / import-x）迁移未完成，非本次改动的模块仍有存量告警 | `prompts/*`、`shared/time.ts` |



## 11 设计决策



| 编号 | 决策 | 收益 | 代价 |

|---|---|---|---|

| D1 | 单包双产物：`lib.ts` 出库产物，`cli.ts` 出可执行产物 | 一套代码两种消费方式，行为不分叉 | 构建两遍，需关闭 `emptyOutDir` |

| D2 | CLI 作为库的参考消费者 | CLI 与库天然同构，架构不会腐化 | CLI 必须容忍「库不做交互」的约束 |

| D3 | 编排下沉到 `domain/commit-flow` | 复用面最大，app 只做适配 | 领域层需显式接收回调而非直接交互 |

| D4 | 错误用稳定 `code` 而非消息文本 | 调用方可编程分支 | 需维护错误码清单，新增错误要同步文档 |

| D5 | `config` 独立成层而非并入 `infra` | 各层均可正向依赖配置，无回边 | 层数量增加 |

| D6 | 提示词集中为 `prompts` 资源层 | 面向模型的文本可统一维护 | 该层依赖 `shared/commit-limits`，需保持单向 |

| D7 | 行宽上限放 `shared` | 提示词与校验器共用同一组数字 | 新增上限需同时改提示词与校验器 |

| D8 | git 执行器端口化（`GitExecutor` 可注入）+ 浏览器纯函数入口 `lib-browser.ts` | 两个 Node 入口（`cli.ts` 与 `lib.ts`）经 `src/node/setup.ts` 的 `setupNodeGitExecutor` 装配 child_process 实现；浏览器 / WebView 入口不装配，改由调用方经 `setGitExecutor` 注入 Tauri IPC 等，同一份纯核可双端复用（F07、S07 §3） | 新增 `node/` 环境适配层（含 `setup.ts`）；构建多出一遍浏览器产物与防回归护栏 |



## 12 改动指引



新增能力时按此顺序落位：



1. 业务规则与校验 → `domain/<子域>/`

2. 外部系统访问（git / LLM）→ `infra/<系统>/`

3. 面向模型的文本 → `prompts/`

4. 与业务无关的工具 → `shared/`（仅当 `prompts` 与 `domain` 都要用时）

5. 终端渲染、提问、退出码 → `app/`

6. 需要对外承诺 → 在 `src/lib.ts` 显式导出，并同步 README 的公共 API 表



禁止事项：



- 禁止在 `domain` / `infra` / `config` 中调用 `console.*`、`question()`、`process.exit`

- 禁止 `infra` 依赖 `prompts`（修复提示由 `domain` 传入）

- 禁止 `domain` 依赖 `app`（含 `CliError` 等 CLI 语义类型）

- 禁止 `shared` 依赖任何上层，或引入终端交互

- 禁止绕过 `src/lib.ts` 从深层路径导入（调用方视角）



## 13 变更记录



2026-10-29 架构收敛：消除 8 项层级违规，依赖方向现已全部符合第 4 节规则。



| 编号 | 收敛项 | 处理 |

|---|---|---|
