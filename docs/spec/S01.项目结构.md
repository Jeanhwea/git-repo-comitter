## 1 定位与边界

`grc`（git-repo-comitter）：读取 git 暂存区变更，调用 OpenAI 兼容接口生成符合 Conventional Commits 的中文提交信息，写入 `git commit`。可作为 CLI（`grc` 命令）或库（Node / 浏览器）被调用。

| 在边界内 | 不在边界内 |
|---|---|
| 变更采集（含二进制识别）、diff 切分与折叠 | 分支管理、push / 远程操作 |
| 提交信息生成、分批合并、格式校验与重试 | 代码改写、格式化、lint |
| 提交前新增文件审查门禁 | LLM 服务自身的部署与鉴权体系 |
| 以库或 CLI 两种方式对外提供上述能力 | git hook 的自动安装与卸载 |

## 3 关键业务流程：一次提交

编排入口 `executeCommit`（`domain/commit-flow.ts:176`），库与 CLI 共用。

| # | 步骤 | 位置 | 失败/分支 |
|---|---|---|---|
| 1 | `apiKey` 为空 → 走规则化兜底，不抛错 | `commit-flow.ts:183` | 调 `generateFallbackMessage`（`fallback.ts:266`） |
| 2 | 校验目标路径是 git 仓库 | `commit-flow.ts:200` | 抛 `NOT_GIT_REPO` |
| 3 | 按调用作用域装配进度输出槽 | `commit-flow.ts:210` | 退出时还原（`:275`） |
| 4 | 暂存：`stagedOnly` 则校验已有暂存，否则 `git add` | `commit-flow.ts:103` | 抛 `NO_STAGED_CHANGES`（`:106`） |
| 5 | 审查门禁：仅在传入 `onReview` 且有新增文件时启用 | `commit-flow.ts:126` | 回调返回 false → 抛 `USER_CANCELLED`（`:151`） |
| 6 | 提取暂存 diff（排除二进制） | `commit-flow.ts:217` | 为空 → 返回 `CommitSkipped(NO_CHANGES)`（`:224`） |
| 7 | 生成提交信息（可能分批） | `commit-flow.ts:238` | 校验失败 `VALIDATION_FAILED` / 空响应 `LLM_FAILED` → 捕获后降级兜底（`:246`） |
| 8 | 执行 `git commit` | `commit-flow.ts:270` | git 报错向上抛 `GIT_FAILED` |
| 9 | 返回 `CommitSuccess`（含 `message` / `batchCount` / `elapsedMs`） | `commit-flow.ts:274` | — |

分批生成（`domain/commit-message/batch.ts:66`）：

| 分支 | 条件 | 位置 |
|---|---|---|
| 直接生成 | `estimateTokens(diff) <= effectiveLimit(config, system)` | `batch.ts:74` |
| 折叠后生成 | 超大块折叠为文件名占位后仍可容纳 | `batch.ts:80`（`collapseOversizedBlocks`）+ `:83` |
| 分批生成 | 按 `groupIntoBatches` 切批 → 逐批出草稿 → `fitWithinBudget` 挑选 → 合并 | `batch.ts:89`~`:126` |

> 兜底降级：步骤 1（无 apiKey）与步骤 7（LLM 失败）两条路径都汇聚到 `tryFallback`（`commit-flow.ts:162`），复用 `getStagedChangeSet` + `generateFallbackMessage` + `gitCommit`，保证「无 LLM / LLM 挂掉」仍可产出合规提交消息。

## 4 分层与依赖规则

```
        ┌─────────────┐   ┌─────────────┐
        │  src/cli.ts │   │ src/lib.ts  │     入口（不属于层）
        │  CLI 启动器 │   │  库公共 API │
        └──────┬──────┘   └──────┬──────┘
               │                 │
        ┌──────▼──────┐          │
        │     app     │          │        终端渲染、命令、交互、退出码
        └──────┬──────┘          │
               │                 │
   ┌───────────▼─────────────────▼───────────┐
   │                 domain                  │  业务编排与校验，唯一业务真相来源
   └───────┬───────────────────┬─────────────┘
           │                   │
   ┌───────▼───────┐   ┌───────▼───────┐
   │     infra     │   │    prompts    │  外部系统访问 / 提示词资源
   └───────┬───────┘   └───────┬───────┘
           │                   │
   ┌───────▼───────────────────▼───────┐
   │              config               │    配置输入（贯穿各层）
   └───────────────┬───────────────────┘
                   │
           ┌───────▼───────┐
           │     shared    │            纯工具，不依赖任何层
           └───────────────┘

   node/ 环境适配层：GitExecutor 的 Node 默认实现（child_process）驻此，
   仅供 Node 入口装配，不属于业务层。
```

| 层 | 允许依赖 | 职责 | 禁止 |
|---|---|---|---|
| `app` | `config` `domain` `shared` | 参数解析、终端渲染、交互提问、退出码翻译 | 承载业务编排；被 `domain`/`infra` 依赖 |
| `domain` | `config` `infra` `prompts` `shared` | 业务编排与结果校验 | 打印、提问、读写文件、调用 `process.exit` |
| `infra` | `config` `shared` | git 进程调用、LLM 传输、token 预算 | 依赖 `prompts`（修复提示由 `domain` 传入）；抛 CLI 语义错误 |
| `prompts` | `shared` | 提示词文本与消息组装 | 依赖 `domain`/`infra`/`app` |
| `config` | `shared` | 配置默认值、收敛、文件读写 | 终端交互、直接 `console.*` |
| `shared` | 仅 `shared` | 日志、进度、错误、校验结论、token 估算、行宽上限 | 依赖任何上层；含终端交互原语 |
| `node` | `infra` `shared` | 环境专有实现（child_process / fs 等） | 被业务层直接 import（只经 `setupNodeGitExecutor` 装配） |

依赖方向实测（2026-10-30 逐文件核对，grep 验证）：

- `domain` 无 `@/app` 引用（无回边）；无 `console.*` / `question()` / `process.exit` 调用。
- `infra` 无 `@/prompts` / `@/domain` / `@/app` 引用（`retry.ts` 的修复提示由 `domain` 调用方以 `repairHint` 参数传入，见 `retry.ts:30`）。
- `config` 仅依赖 `shared`（且 `user-file.ts` 对 `shared/logger` 为同层正向依赖）。
- `shared` 仅内部互相引用（`logger.ts:12` 引 `./time`），不引任何上层。
- `prompts` 仅依赖 `shared/commit-limits`（5 处，见 §13 一致性校验 C3），不依赖任何业务层。
- `node/` 仅被 `cli.ts` / `lib.ts` 经 `setupNodeGitExecutor` 装配引用，业务层不直接 import。

## 6 双入口

| 入口 | 源文件 | 产物 | 消费者 |
|---|---|---|---|
| 库（Node） | `src/lib.ts` | `dist/index.js`（ESM）、`dist/index.cjs`（CJS）、`dist/types/lib.d.ts` | 外部代码（Node） |
| CLI | `src/cli.ts` | `dist/cli.cjs`（带 shebang） | `grc` / `git-repo-comitter` 命令 |
| 浏览器库 | `src/lib-browser.ts` | `dist/browser/index.js`（ESM）、`dist/types/lib-browser.d.ts` | 浏览器 / WebView 经 `git-repo-comitter/browser` 子路径导入 |

两个 Node 入口（`cli.ts` 与 `lib.ts`）在加载时均须调用 `setupNodeGitExecutor()` 装配默认 git 执行器；浏览器入口 `lib-browser.ts` 不装配、也不暴露任何 git 符号（强制约定见 S07 §3 E1，护栏见 `scripts/check-browser-entry.mjs:104`）。

库入口是**唯一对外承诺**：只有 `src/lib.ts` 导出的符号属于契约，其余模块可随版本调整。

公共 API 分组（`src/lib.ts:24`~`:79`）：

| 分组 | 符号 |
|---|---|
| 编排 | `commit`（= `executeCommit`）、`CommitRequest` / `CommitOutcome` / `CommitSuccess` / `CommitSkipped` |
| 生成与校验 | `generateCommitMessage`、`generateCommitMessageBatched`、`validateCommitMessage` |
| git | `getStagedDiff`、`gitCommit` |
| 配置 | `resolveConfig`、`loadDefaultConfig`、`loadUserConfigFile`、`AppConfig` / `LLMConfig` / `UserConfig` |
| 横切 | `GrcError` / `GrcErrorCode`、`setLogLevel` / `setLogSink`、`setProgressSink` / `getProgressSink` |

> 一致性注意：git 执行器端口 `setGitExecutor`（`infra/git/executor.ts:37`）**未**进入 `lib.ts` / `lib-browser.ts` 的公开导出，浏览器护栏还显式断言它不在浏览器公共 API 中（见 §13 C1）。因此「浏览器入口由调用方经 `setGitExecutor` 注入」仅在文档文字中出现，代码层面实际不可达——真实浏览器流程由宿主算好 diff 后以字符串传入 `generateCommitMessage`。请勿在调用方依赖该注入路径。

CLI 是库的参考消费者：`app/commands/commit.ts:34` 调用的正是 `executeCommit`，因此两者不存在两套行为。

浏览器入口 `src/lib-browser.ts` 是**纯函数侧子集**：仅导出配置（`resolveConfig` / `loadDefaultConfig`）+ 生成（`generateCommitMessage` / `generateCommitMessageBatched`）+ 校验（`validateCommitMessage`）+ 横切（`GrcError` / 日志 / 进度），不导出任何 git 读写能力（`getStagedDiff` / `gitCommit`）与 Node 文件 IO（`loadUserConfigFile` / `saveUserConfig`），使其 import 图零 Node 内置模块、可在浏览器 / WebView 直接打包（F07）。

| 行宽上限 | `shared/commit-limits.ts`：标题 78、正文行 118、要点 10 条 | 提示词与校验器共用同一组数字 |
| 进度槽/日志槽 | 模块级单例（`shared/progress.ts:15`、`shared/logger.ts:30`） | 未装配即静默 / 默认 info |

## 9 数据流

```
CLI:   grc [-s] → app/cli/program → app/commands/commit
                                     ├─ 读 ~/.grc/config.json（app/config/load）
                                     ├─ onProgress = console.log
                                     └─ onReview   = 终端问答（app/steps/review）
                                          ↓
库:    commit({ config, repoPath, stagedOnly, onProgress, onReview })
                                          ↓
       domain/commit-flow.executeCommit
         ├─ infra/git/repo      isGitRepo / gitAddAll / gitCommit
         ├─ infra/git/changes   getStagedChangeSet / readNewFileContents
         ├─ infra/git/diff      getStagedDiff（切块、折叠、分批，二进制过滤）
         ├─ prompts             buildMessages（system + user）
         ├─ infra/llm/transport chatCompletion → extractContent
         ├─ infra/llm/retry     callWithValidation（校验失败附修复提示重试）
         ├─ domain/*/checker    validateCommitMessage / validateReviewResult
         └─ shared/progress     emitProgress（可静默）
                                          ↓
       返回 CommitOutcome（结构化）→ CLI 渲染 或 调用方自行处理
```

浏览器链路：宿主（Rust / Node）算好 diff → 以字符串传入 `generateCommitMessage(diff, config)`（`lib-browser.ts` 导出），不触发任何 git 进程，也不依赖 `setGitExecutor`。

## 11 设计决策

| 编号 | 决策 | 收益 | 代价 |
|---|---|---|---|
| D1 | 单包双产物：`lib.ts` 出库产物，`cli.ts` 出可执行产物 | 一套代码两种消费方式，行为不分叉 | 构建两遍，需关闭 `emptyOutDir` |
| D2 | CLI 作为库的参考消费者 | CLI 与库天然同构，架构不会腐化 | CLI 必须容忍「库不做交互」的约束 |
| D3 | 编排下沉到 `domain/commit-flow` | 复用面最大，app 只做适配 | 领域层需显式接收回调而非直接交互 |
| D4 | 错误用稳定 `code` 而非消息文本 | 调用方可编程分支 | 需维护错误码清单，新增错误要同步文档 |
| D5 | `config` 独立成层而非并入 `infra` | 各层均可正向依赖配置，无回边 | 层数量增加 |
| D6 | 提示词集中为 `prompts` 资源层（依赖 `shared/commit-limits`） | 面向模型的文本可统一维护 | 该层依赖 shared，需保持单向 |
| D7 | 行宽上限放 `shared` | 提示词与校验器共用同一组数字 | 新增上限需同时改提示词与校验器 |
| D8 | git 执行器端口化（`GitExecutor` 可注入）+ 浏览器纯函数入口 `lib-browser.ts` | 两个 Node 入口经 `node/setup.ts` 装配；浏览器只复用纯核，不在公共 API 暴露 git 符号 | 新增 `node/` 环境适配层；构建多出一遍浏览器产物与防回归护栏 |

## 12 改动指引

新增能力时按此顺序落位：

1. 业务规则与校验 → `domain/<子域>/`
2. 外部系统访问（git / LLM）→ `infra/<系统>/`
3. 面向模型的文本 → `prompts/`
4. 与业务无关的工具 → `shared/`（仅当 `prompts` 与 `domain` 都要用时）
5. 终端渲染、提问、退出码 → `app/`
6. 需要对外承诺 → 在 `src/lib.ts` 显式导出，并同步 README 的公共 API 表

禁止事项：

- 禁止在 `domain` / `infra` / `config` 中调用 `console.*`、`question()`、`process.exit`
- 禁止 `infra` 依赖 `prompts`（修复提示由 `domain` 传入）
- 禁止 `domain` 依赖 `app`（含 `CliError` 等 CLI 语义类型）
- 禁止 `shared` 依赖任何上层，或引入终端交互
- 禁止绕过 `src/lib.ts` 从深层路径导入（调用方视角）
- 禁止新增 Node 入口而不首行调用 `setupNodeGitExecutor()`（S07 §3 E1）
