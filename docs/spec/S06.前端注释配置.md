| `prettier` | 代码格式化（保持注释对齐等风格一致） |

## 2. ESLint 配置（扁平化配置）

使用 ESLint v10 的扁平化配置格式 `eslint.config.js`。

### 2.1 排除目录

```javascript
globalIgnores(["dist/**", "out/**", "src-tauri/**", "src/components/ui/**", "temp/**", ".next/**"])
```

- `src/components/ui/`：shadcn/ui 基础组件，不加注释、不参与 lint

### 2.2 JSDoc 预设

采用 `eslint-plugin-jsdoc` v64 的**拆分式预设**，整体启用 `flat/logical-typescript-flavor-error` 错误检测预设：

```javascript
{
  files: ["src/**/*.{ts,tsx}"],
  ...jsdoc.configs["flat/logical-typescript-flavor-error"],
}
```

JSDoc mode 设置为 `"typescript"`（禁止大括号类型）：

```javascript
settings: {
  jsdoc: {
    mode: "typescript",
  },
}
```

### 2.3 注释相关规则

#### 语法

| 规则 | 等级 | 检查内容 |
|---|---|---|
| `tsdoc/syntax` | error | TSDoc 语法：标签拼写、`{@link}` 内联标签、花括号转义 |

#### 逻辑校验（来自 jsdoc logical 预设，整体启用）

| 规则 | 检查内容 |
|---|---|
| `jsdoc/check-param-names` | `@param` 名与函数签名参数一致 |
| `jsdoc/check-tag-names` | 标签名合法（防拼写错误如 `@Param`） |
| `jsdoc/check-property-names` | `@property` 名称不重复且嵌套有根 |
| `jsdoc/check-access` | `@access` 标签值合法 |
| `jsdoc/check-values` | `@kind` 等标签的取值合法 |
| `jsdoc/check-types` | 类型写法（写了才查） |
| `jsdoc/no-types` | **禁止** `@param`/`@returns` 写大括号类型（TS 签名已含类型） |
| `jsdoc/no-bad-blocks` | 误用 JSDoc 块注释的坏块 |
| `jsdoc/no-defaults` | 禁止 `@default` 默认值标签 |
| `jsdoc/empty-tags` | 应为空的标签（`@readonly` 等）不能带内容 |
| `jsdoc/escape-inline-tags` | 描述正文里的 `@tag` 字样（会被误解析为标签） |
| `jsdoc/implements-on-classes` | `@implements` 只能用于类 |
| `jsdoc/valid-types` | 所有标签的类型/namepath 语法合法 |
| `jsdoc/require-returns-check` | `@returns` 与实际返回值匹配 |
| `jsdoc/require-yields-check` | `@yields` 与生成器实际产出匹配 |

#### 必填项

| 规则 | 等级 | 检查内容 |
|---|---|---|
| `jsdoc/require-param` | error | 带参函数的注释必须写全所有 `@param`（解构 props 豁免） |
| `jsdoc/require-param-name` | error | `@param` 必须有参数名 |
| `jsdoc/require-param-description` | error | `@param` 必须有描述（防空壳参数说明） |
| `jsdoc/require-returns-description` | error | `@returns` 必须有描述 |

#### 风格统一

| 规则 | 等级 | 检查内容 |
|---|---|---|
| `jsdoc/check-alignment` | error | 块内星号对齐 |
| `jsdoc/multiline-blocks` | error | 单行/多行块格式 |
| `jsdoc/no-blank-block-descriptions` | error | 空描述注释 |
| `jsdoc/no-multi-asterisks` | error | 多余的连续星号 |
| `jsdoc/require-hyphen-before-param-description` | error | `@param name - 描述` 统一带连字符 |
| `jsdoc/tag-lines` | error | 标签之间及标签与描述之间不留空行（紧凑风格） |

#### 显式关闭的规则

| 规则 | 原因 |
|---|---|
| `jsdoc/check-syntax` | 与 `tsdoc/syntax` 职责重叠 |
| `jsdoc/no-undefined-types` | 无法解析 TS 导入类型，易误报 |

### 2.4 未启用的常见规则及原因

| 未启用规则 | 原因 |
|---|---|
| `require-jsdoc` / `require-example` | 注释按需添加，不强制每个导出都有注释 |
| `require-param-type` / `require-returns-type` | 不写 JSDoc 大括号类型——已由 `no-types` 强制禁止 |
| `require-returns` | `@returns` 按需填写，React 组件返回 JSX 自明 |
| `require-throws` / `require-yields` | 本标准未约定 `@throws`/`@yields` 标签 |
| `check-line-alignment` / `lines-before-block` / `require-asterisk-prefix` | 过度格式化，收益低于维护成本 |

## 4. TypeScript 配置（注释相关）

`tsconfig.json` 中注释相关的选项：

```json
{
  "compilerOptions": {
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noUncheckedIndexedAccess": true,
    "strictNullChecks": true,
    "types": ["node"]
  }
}
```

**`noUnusedLocals` / `noUnusedParameters`**：间接确保废弃代码不会被注释掩盖。

此外，ESLint 中配置了 `@typescript-eslint/no-unused-vars`，用 `_` 前缀豁免占位参数：

```javascript
"@typescript-eslint/no-unused-vars": [
  "error",
  {
    "argsIgnorePattern": "^_",
    "varsIgnorePattern": "^_"
  }
]
```

完整的 ESLint 配置参考：

import tseslint from "typescript-eslint";
import importX from "eslint-plugin-import-x";
import tsdoc from "eslint-plugin-tsdoc";
import jsdoc from "eslint-plugin-jsdoc";

export default defineConfig(
  globalIgnores(["dist/**", "out/**", "src-tauri/**", "src/components/ui/**", "temp/**", ".next/**"]),

  js.configs.recommended,
  ...tseslint.configs.recommended,

  {
    files: ["scripts/**/*.mjs"],
    languageOptions: {
      ecmaVersion: 2022,
      sourceType: "module",
      globals: {
        console: "readonly",
        process: "readonly",
        URL: "readonly",
      },
    },
  },

  // JSDoc 逻辑预设（错误检测类规则）
  {
    files: ["src/**/*.{ts,tsx}"],
    ...jsdoc.configs["flat/logical-typescript-flavor-error"],
  },

  {
    files: ["src/**/*.{ts,tsx}"],
    plugins: {
      "import-x": importX,
      tsdoc,
      jsdoc,
    },
    settings: {
      "import-x/resolver": {
        typescript: true,
      },
      jsdoc: {
        mode: "typescript",
      },
    },
    rules: {
      // Import 顺序
      "import-x/order": [
        "error",
        {
          groups: ["builtin", "external", "internal", "parent", "sibling", "index"],
          "newlines-between": "always",
          alphabetize: { order: "asc", caseInsensitive: true },

      "import-x/no-duplicates": "error",

      // TypeScript
      "@typescript-eslint/no-unused-vars": [

        { argsIgnorePattern: "^_", varsIgnorePattern: "^_" },

      "tsdoc/syntax": "error",

      // JSDoc 必填项
      "jsdoc/require-param": [
        "error",
        { checkDestructured: false, checkDestructuredRoots: false },

      "jsdoc/require-param-name": "error",
      "jsdoc/require-param-description": "error",
      "jsdoc/require-returns-description": "error",

## 7. 注释校验与修复工作流

### 7.1 四步流程

1. **写完注释后运行** `pnpm lint`
2. **阅读输出，定位问题**——格式：`文件 → 行号:列号 → 问题描述 → 规则名`
3. **按规则名查表修复**
4. **重跑 `pnpm lint`，直到通过**（退出码 0、无任何 error）

### 7.2 常见报错及修复

| 报错 | 原因 | 修复 |
|---|---|---|
| `tsdoc-malformed-inline-tag` | 注释正文花括号被当作内联标签 | 用 `\{` `\}` 转义 |
| `jsdoc/check-param-names` | `@param` 名与函数签名不一致 | 同步参数名 |
| `jsdoc/require-param` | 带参函数写注释但漏了 `@param` | 补全所有 `@param` |
| `jsdoc/no-types` | `@param {string} name` 写了类型 | 改成 `@param name - 描述` |
| `jsdoc/require-hyphen-before-param-description` | `@param` 描述前漏了连字符 | 加 ` - ` |
| `jsdoc/tag-lines` | 标签之间留了空行 | 删掉空行（`lint:fix` 可自动修复） |

## 8. 注释标准参考

注释的核心理念和书写规范要点摘要：

- **注释应传递代码名称无法表达的信息**——为什么做、什么场景、有什么副作用
- **能单行不写多行，不加胜过坏注释**
- **统一使用中文 TSDoc**，描述用中文，参数名保持英文
- 自明的导出（`getXxx`、纯类型别名）不加多余注释
- 接口字段用行前 `/** */`，不用行尾 `//`
- `@param` 写所有参数（解构 props 豁免），统一 `@param name - 描述` 格式
- 标签之间及标签与描述之间不留空行（紧凑风格）
- 事件常量注明触发时机与方向
- 算法函数有分段主线注释
- `@deprecated` 必须带迁移指引
- shadcn 组件（`src/components/ui/`）不加任何注释
