# 架构与编码规范总纲

本文件是 grc 的**规范总纲（原则层）**。它不重复 S01《项目结构》的分层细节与模块清单，也不替代 F 系列功能规格，而是把散落在各处、需要「跨模块一致遵守」的规则与红线集中成一份清单。新增代码、新增入口、新增环境适配时，先过本文件；与 S01 / F07 冲突时以本文件为准，并回改对应文档。

## 1 适用范围与文档关系

| 文档 | 角色 | 本文件如何引用 |
|---|---|---|
| S01《项目结构》 | 具体架构：分层、依赖方向、模块清单、业务编排 | 本文件 §2 / §3 / §8 的原则在 S01 有逐文件落实 |
| F07《浏览器环境适配》 | 端口化 + 浏览器入口的设计与接线 | 本文件 §4 的端口适配约定在 F07 展开 |
| F / I 系列 | 单功能 / 单问题的规格与方案 | 单点规则以本文件为准，矛盾时回改 F / I |

**原则**：文档以源码为准；源码改动若推翻了某条规则，必须同步回改本文件（及其引用的 S01 / F07），不能只改代码。

## 2 分层与依赖总则

分层见 S01 §4（领域对象在 `domain`，外部系统在 `infra`，面向模型的文本在 `prompts`，贯穿各层的配置在 `config`，纯工具在 `shared`；`app` 只做终端适配与退出码）。本文件只重申红线：

- **依赖方向单向向下**：`app → domain → {infra, prompts} → config → shared`。`shared` 不依赖任何上层，且不含终端交互。
- **端口在 `infra`，实现在 `node/`**：可注入的能力（如 git 执行）其**接口与注册表**留在 `infra/<系统>/`（零环境依赖），**具体实现**放在 `node/<系统>/`（Node 专有，可 import `child_process` / `fs` 等）。`node/` 是环境适配层，不属于业务层，仅供 Node 入口装配。
- **禁止回边**：`domain` / `infra` / `config` 不得依赖 `app`（含 `CliError` 等 CLI 语义类型）；`infra` 不得依赖 `prompts`（修复提示由 `domain` 传入）。
- **公共 API 唯一出口**：只有 `src/lib.ts` 导出的符号是稳定契约；调用方禁止从深层路径 import。浏览器侧以 `src/lib-browser.ts` 导出的纯函数子集为准。

## 3 入口契约（强制）

项目有三个入口，职责严格分离：

| 入口 | 源文件 | 产物 | 装配默认 git 执行器？ |
|---|---|---|---|
| 库（Node） | `src/lib.ts` | `dist/index.js` / `dist/index.cjs` | ✅ 是 |
| CLI | `src/cli.ts` | `dist/cli.cjs` | ✅ 是 |
| 浏览器库 | `src/lib-browser.ts` | `dist/browser/index.js` | ❌ 否 |

> ⚠️ **强制约定 E1（本次修复确立）**：**所有 Node 入口（`cli.ts` 与 `lib.ts`）必须在加载时调用 `setupNodeGitExecutor()` 装配默认 git 执行器；浏览器 / WebView 入口（`lib-browser.ts`）不装配，也不得导出 `setGitExecutor`。**
>
> 原因：git 执行器（`GitExecutor`）是端口，默认实现（`childProcessExecutor`）只在 Node 环境有意义。`execGit` 在未装配时抛 `GrcError(GIT_FAILED)`，而非静默失败。若某个 Node 入口漏掉装配，该入口一调 `getStagedDiff` / `gitCommit` 就会在运行时炸出「git 执行器未装配」。历史上 CLI 入口因未装配而失效，正是此类遗漏。
>
> 浏览器 / WebView 不使用 git 端口：其公共 API（`lib-browser.ts`）不导出 `setGitExecutor` / `getStagedDiff` / `gitCommit`，由 `scripts/check-browser-entry.mjs` 护栏断言缺失；宿主（Rust / Node）自行算好 diff 后以字符串传入 `generateCommitMessage`。**不要**在文档或调用方中声称「浏览器经 `setGitExecutor` 注入」——该路径在公共 API 中不存在。
>
> 实现位置：装配逻辑统一收敛到 `src/node/setup.ts` 的 `setupNodeGitExecutor()`，两个 Node 入口都调用它，**不要**在入口里直接 `import { setGitExecutor }` + `import { childProcessExecutor }` 重复装配（避免两处漂移）。新增 Node 入口时，第一行必须是 `setupNodeGitExecutor()`。

**其余入口红线**：

- 库入口是**唯一对外承诺**：只有 `lib.ts` 导出的符号属于契约，其余模块可随版本调整。
- CLI 是库的**参考消费者**：`app/commands/commit.ts` 调用的就是 `domain/commit-flow.executeCommit`，CLI 与库不存在两套行为。
- 浏览器入口的 import 图**零 Node 内置模块**（`fs` / `os` / `path` / `child_process` / `readline/promises` 均不得出现），其能力是纯函数子集（配置解析、生成、校验、横切），不导出任何 git 读写与文件 IO。该约束由 `scripts/check-browser-entry.mjs` 护栏守护。

## 4 端口与适配总则

- 环境相关能力（git 进程、配置文件 IO、LLM 传输）一律**端口化**：接口 + 注册表在 `infra`，实现在 `node/`，调用方经注册表取用，不直接 new 具体实现。
- Node 侧在入口加载时**装配默认实现**；非 Node 侧（浏览器 / WebView）**不装配 git 端口**，而是由宿主算好 diff 后以字符串传入 `generateCommitMessage`，同一份纯核可多端复用（详见 E1 说明与 F07）。
- 端口契约尽量保持同步（如 `GitExecutor` 为同步签名），避免为适配异步宿主而破坏库契约；异步需求走独立评估（见 F07「明确不做」）。
- 未装配即调用必须**显式失败**（抛带 `code` 的 `GrcError`），严禁静默返回空 / 假成功。

## 5 错误处理总则

- 业务错误用稳定 `code`（`GrcErrorCode`），不用消息文本做分支依据；新增错误码须同步 S01 §7 与 `shared/errors.ts`。
- 库与领域层**只抛不退出**：`process.exit` 仅允许出现在 `app/cli/program.ts` 的 `handleCliError`（`code → 退出码` 翻译表处）。
- 失败要可诊断：`GIT_FAILED` / `LLM_FAILED` 等须携带可读原因；不要吞掉底层 stderr（见 S01 风险 R2）。
- 进度与日志是**模块级可接管**机制（`setProgressSink` / `setLogSink`），未装配时静默，不报错——这与「执行器未装配即报错」是两回事，勿混淆。

## 6 配置总则

- `resolveConfig` 是纯函数（不读写文件），浏览器可复用；文件读写下沉到 `config/user-file.ts`（`loadUserConfigFile` / `saveUserConfig`），浏览器入口不导入该模块。
- 库不自动读 `~/.grc`，配置由调用方显式传入；CLI 的超限告警与交互式修复在 `app/config/load.ts`。
- 配置字段缺省收敛走 `loadDefaultConfig` / `clampLlm`，上限数字（token 额度、行宽）集中在 `shared/commit-limits.ts` 等常量处，改动须同时看提示词与校验器（见 S01 风险 R3）。

## 7 命名与注释约定

- **语言**：源码注释统一使用**中文**；标识符、技术名词保留英文（`GitExecutor`、`execGit`、`childProcessExecutor` 等）。
- **标识符**：函数 / 变量 `camelCase`，类型 / 接口 `PascalCase`，错误码常量 `UPPER_SNAKE`（`GIT_FAILED`）；路径别名 `@/` 指向 `src/`，禁止相对路径跨层深跳。
- **注释对象**：注释讲「为什么 / 约束」，不重复「做什么」；端口、注入点、环境差异处必须写明「谁装配 / 谁注入 / 为何 Node 专有」。
- **提交信息**：仓库自身提交遵循 Conventional Commits（见 F04），与工具生成的消息共用同一套校验器。

## 8 构建与产物约定

- 三套产物由 `scripts/build.mjs` 编排：`lib`（ESM + CJS）→ `cli`（CJS + shebang）→ `browser`（ESM）→ 类型声明 → 浏览器入口护栏，顺序不可乱（`cli` / `browser` 关闭 `emptyOutDir` 以保留库产物）。
- `vite.*.config.ts` 的 `external` 列表（Node 内置模块 + `openai` / `commander` / `yaml`）是「这些模块永不进产物、运行时由宿主提供」的声明；新增 Node 专有依赖须同步此处。
- 浏览器产物受 `scripts/check-browser-entry.mjs` 守护：禁止 Node 内置模块引用、git 符号不得泄漏到公共 API。
- 改动后必须跑通 `pnpm check`（tsc）、`pnpm lint`、`pnpm build` 三道；格式用 Prettier，Windows 下 `format:check` 需 `--end-of-line crlf`。

## 9 改动落位与禁止项

新增能力按 S01 §12 顺序落位：`domain` → `infra` → `prompts` → `shared` → `app` → 对外则在 `src/lib.ts` 显式导出并同步公共 API 表。

**全局禁止**：

- 禁止在 `domain` / `infra` / `config` 调用 `console.*`、`question()`、`process.exit`。
- 禁止 `infra` 依赖 `prompts`、禁止 `domain` 依赖 `app`、禁止 `shared` 依赖任何上层或引入终端交互。
- 禁止绕过 `src/lib.ts` 从深层路径 import。
- 禁止新增 Node 入口而不调用 `setupNodeGitExecutor()`（见 §3 强制约定 E1）。
- 禁止把异步宿主的 git 实现硬接进同步 `GitExecutor` 契约（破坏 F05 公开契约）。

## 10 强制清单（上线前自检）

- [ ] 新增 / 修改的模块 `@/` 引用方向符合 §2 分层，无回边。
- [ ] 新增 Node 入口首行调用 `setupNodeGitExecutor()`；浏览器入口 import 图零 Node 内置模块且通过护栏。
- [ ] 环境能力走端口：接口在 `infra`、实现在 `node`、入口装配或调用方注入。
- [ ] 错误用稳定 `code`，库 / 领域层只抛不退出，原因可读。
- [ ] 配置改动同步提示词与校验器；`resolveConfig` 保持纯函数。
- [ ] 对外符号只在 `src/lib.ts` 导出，并同步 S01 §6 公共 API 表与 README。
- [ ] 跑通 `pnpm check` / `pnpm lint` / `pnpm build`（含浏览器护栏）。
- [ ] 文档改动（S01 / F07 / 本文件）与代码一致，无遗漏。
