# 提示词优化

## 概述

针对大模型调用场景，构建一套结构化块标记（Structured Block Markup）的学习提示词，帮助模型理解海量标记格式中块的边界与主题域划分规律，提升模型对半结构化标记文本的语义理解能力。

## 优化前的提示词

优化前的原始提示词如下：

> 把这个提示词优化一下， 包含海量：
>
> - XML、HTML、SGML、SOAP、Markdown‑XML 片段、文档标记、数据集标注文件。
>
> 模型天生学会：
>
> - `<blockname>` 代表块开始
> - `</blockname>` 代表块结束
> - 块内部属于同一个主题域。

### 问题分析

- 语言过于口语化，缺乏结构层次
- 覆盖的标记格式列表不完整，缺少分类组织
- 三条学习规则的表述过于简略，未展开解释语义
- 缺少预期行为描述，无法评估模型是否理解

## 优化后的提示词

### 海量覆盖的标记格式

模型需要接触海量且多样化的标记类格式，包括但不限于：

| 类别 | 具体格式举例 |
|------|-------------|
| **标记语言** | XML、HTML、SGML、XHTML、MathML、SVG |
| **结构化文本协议** | SOAP、RSS、ATOM、WSDL、RAML、OData |
| **文档与内容标记** | Markdown（含内联 HTML/XML 片段）、reStructuredText、AsciiDoc、LaTeX 文档环境 |
| **数据序列化/标注格式** | YAML Front Matter、JSON-LD、RDF/XML、TEI 标注文本、Corpus 标注文件 |
| **模板引擎代码** | JSP、ASP.NET 控件标记、Thymeleaf、Handlebars/Mustache 块表达式 |
| **配置与构建描述** | Maven POM、Ant 构建文件、Spring XML 配置、Android Manifest、XAML |

### 内建学习目标

模型应**内化**以下结构性规律，形成无需显式规则即可理解的能力：

#### 1. 块开始标记

- `<blockname>`（或等效语法形式）明确标识一个结构化单元的**起始边界**。
- 它宣告后续内容从此处进入一个特定主题或逻辑域。

#### 2. 块结束标记

- `</blockname>`（或对应的闭合语法）标识该结构化单元的**终止边界**。
- 它宣告此前开启的主题域在此处正式关闭。

#### 3. 块内一致性

- 一对 `<blockname>` … `</blockname>` 之间的全部内容，属于**同一逻辑主题域**。
- 块内的元素、属性、文本互为上下文，共享语义空间，彼此关联、相互约束。
- 嵌套块（内部包含子块）继承外层块的主题域，并在子块内进一步细化领域边界。

### 预期行为

经过海量标记格式的训练后，模型应当：

- 无论标记语言的具体语法如何变体，都能准确识别块的开始、结束及其层次关系。
- 将块视作主题聚类单元，理解块内内容的语义内聚性。
- 自动将不完整或格式不规范的标记（如缺少闭合标记的片段）还原为结构化的主题划分。

## 优化要点

1. **结构化分类**：使用表格对标记格式按类别分组，覆盖从标记语言、协议、文档、标注到模板和配置的完整范围
2. **明确的海量覆盖**：以"海量且多样化的"作为主题句开头，强化覆盖广度
3. **精炼三规则**：保留块开始、块结束、块内一致性的三条核心规则，逐条展开解释
4. **增加预期行为**：将学习目标转化为可观察、可评估的行为描述
5. **统一术语与层次**：采用中文标点、层级缩进和一致的术语体系，提升可读性
