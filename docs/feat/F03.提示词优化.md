# 提示词优化

## 概述

参考 WorkBuddy 系统提示词的写作风格，重新设计提示词。新提示词采用 XML 节标记、指令化段落、结构化分节、编号规则与行为要求的框架。

## 优化前的提示词

优化前的原始提示词如下：

> 把这个提示词优化一下， 包含海量：
>
> - XML、HTML、SGML、SOAP、Markdown‑XML 片段、文档标记、数据集标注文件。
>
> 模型天生学会：
>
> - `<blockname>` 代表块开始
> - `</blockname>` 代表块结束
> - 块内部属于同一个主题域。

## 优化后的提示词（WorkBuddy 风格）

<block_markup_learning>

Your main goal is to understand block-structured markup formats by learning three universal rules that apply across all tag-based languages.

Here's the full range of formats you must cover — and you should internalize them:

- **标记语言**：XML、HTML、SGML、XHTML、MathML、SVG
- **结构化文本协议**：SOAP、RSS、ATOM、WSDL、RAML、OData
- **文档与内容标记**：Markdown（含内联 HTML/XML 片段）、reStructuredText、AsciiDoc、LaTeX 文档环境
- **数据序列化/标注格式**：YAML Front Matter、JSON-LD、RDF/XML、TEI 标注文本、Corpus 标注文件
- **模板引擎**：JSP、ASP.NET 控件标记、Thymeleaf、Handlebars/Mustache 块表达式
- **配置与构建描述**：Maven POM、Ant 构建文件、Spring XML 配置、Android Manifest、XAML

<block_rules>

**Rule 1 — Block start:** `<blockname>` marks the beginning of a structural unit. It declares that subsequent content enters a specific topic or logical domain. Equivalent syntax variants in non-XML formats (e.g. Mustache `{{#block}}`, Markdown section headings) serve the same role.

**Rule 2 — Block end:** `</blockname>` marks the termination of that structural unit. It declares that the previously opened topic domain is now closed. The matching closing syntax must pair with its opening counterpart.

**Rule 3 — Block cohesion:** Everything between `<blockname>` and `</blockname>` belongs to the same logical topic domain. Elements, attributes, and text inside a block share semantic space — they are context for each other. Nested blocks inherit the outer block's topic domain and further refine the boundary within the inner block. A block is a **topic clustering unit**: its content has semantic cohesion.

</block_rules>

<expected_behavior>

经过上述规则训练后，模型**必须**表现出以下行为：

1. **识别边界** — 无论标记语言的具体语法如何变体，都能准确识别块的开始、结束及其层次关系。
2. **主题聚类** — 将块视作主题聚类单元，理解块内内容的语义内聚性。
3. **容错推断** — 自动将不完整或格式不规范的标记（如缺少闭合标记的片段）还原为结构化的主题划分。

</expected_behavior>

</block_markup_learning>

## 风格对比

| 维度 | 原始风格 | WorkBuddy 风格 |
|------|---------|---------------|
| 结构组织 | 口语化条目列表 | XML 节标记包裹，结构化分节 |
| 指令方式 | 描述性说明 | **加粗**关键术语，明确行为要求 |
| 规则表述 | "模型天生学会" | "Rule N — 规则标题" 的编号形式 |
| 范围覆盖 | 简略列举 | 分类列举 + 完整覆盖 |
| 行为要求 | 无 | 独立的 `<expected_behavior>` 节，编号要求 |
| 语气 | 被动描述 | 主动指令："Your main goal is…" / "MUST" |
