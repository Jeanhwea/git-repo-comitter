# F09. 支持跳过 Git 提交的 Hook

## 背景
有时执行 Git 提交时，仓库会挂一些 Hook（如 lint 测试）。一旦 Hook 脚本报错，提交就会被拦截，无法完成。

## 现状
- Git commit 自身带有一个可跳过 Hook 的参数，提交时带上该参数即可绕过 Hook 检查。
- 但在 GRC 的提交流程里，没有等价的可跳过选项；一旦 Hook 报错，用户就卡在提交这一步，只能去改 Hook 脚本。

## 差距
- GRC 缺少「跳过 Git Hook」的能力，与 git commit 原生参数能力不对等。
- 用户临时只想提交、又不想（或暂时无力）修复报错的 Hook 时，没有便捷路径，只能手工改 Hook 或回到命令行。

## 路径
- 在 GRC 的提交流程中增加「跳过 Git Hook」选项。
- 用户勾选后，GRC 执行 git commit 时带上对应跳过参数，从而绕开 Hook 检查。
- 目标是一键跳过，免去手工修改/调试 Hook 脚本的负担。

## 开放问题
- 具体对应 git commit 的哪个参数（`--no-verify`？）需在实现时确认。
- 该选项在 GRC 的 UI/交互上如何呈现（勾选项 / 命令行 flag / 快捷键）。
- 是否需要更细粒度控制（跳过全部 Hook，还是仅跳过 pre-commit / commit-msg 等指定 Hook）。
- 是否需要安全/风险提示（跳过 Hook 可能产生未经校验的提交）。

## 结论
核心诉求：GRC 需要提供「一键跳过 Git Hook」的提交选项，等价于 git commit 的跳过参数，降低临时提交的摩擦。
