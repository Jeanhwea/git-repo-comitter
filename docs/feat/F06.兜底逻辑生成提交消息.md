# F06 兜底逻辑生成提交消息

## 背景

当用户**未配置 LLM（大模型）**时，`executeCommit` 无法调用 LLM 生成提交消息。此时需要一个兜底逻辑，不依赖外部 API，仅凭仓库本身信息构造一条有意义的提交消息，使用户在无模型可用时不至于被阻塞。

> **典型场景**：`grc init` 时用户跳过 LLM 配置（直接回车），或配置文件中 `llm.model` 为空/无效。此时提交不应抛错中止，而应fallback到本地规则生成的消息。

## 约定

- 大模型没有设置，指 `config.llm` 为空、`llm.model` 为空/缺省、或者已经约定的 NoModel 等标识。
- 兜底消息生成**不允许任何外部网络请求**，只依赖本地 git 信息和项目文件信息。
- 兜底消息**必须包含 `[auto]` 前缀**，以便与 LLM 生成的消息区分。
- 兜底消息的模板参考 `DefaultMessageTemplate`（即 `<type> (<scope>): <subject>` 的 Conventional Commit 格式）。

## 触发条件

在 `executeCommit` 中，生成提交信息前判断 `config.llm` 是否可达：

```
1. config.llm 为 null / undefined → 使用兜底消息
2. config.llm.model 为空串或 "no-model" → 使用兜底消息
3. LLM API 调用失败 → 不自动 fallback（抛出 GrcError，由调用方决定如何处理）
```

> 注意：只有**配置层面的缺失**才触发兜底。API 调用失败（网络超时、认证失败等）不应静默 fallback，避免掩盖配置正确但服务不可用的问题。

## 兜底消息生成规则

### 核心思路

利用 `git log --oneline -1` 获取上一次提交的描述作为参考，再结合本次 diff 的统计信息拼接出一条合理的 auto 消息。

### 实现位置

`src/commit.ts` 中 `generateCommitMessageBatched` 被调用前做判断：

```ts
if (!config.llm || !config.llm.model || config.llm.model === "no-model") {
  return generateFallbackMessage(diff);
}
```

### 实现细节

```ts
// 伪代码示意
function generateFallbackMessage(diff: string, repoPath?: string): { message: string } {
  const lastCommit = execGit(["log", "--oneline", "-1", "--no-color"], {
    allowFailure: true,
    cwd: repoPath,
  }).trim();

  const stats = extractDiffStats(diff); // 提取 diff 中的变更统计
  // stats: { filesCount, additions, deletions, language }

  const prefix = lastCommit
    ? `[auto] (chore): 增量补丁 (基于: ${lastCommit})`
    : `[auto] (chore): 初始提交`;

  const body = [
    stats.filesCount > 0 ? `  ${stats.filesCount} 个文件已变更` : "",
    stats.additions > 0 ? `  ${stats.additions} 行增加` : "",
    stats.deletions > 0 ? `  ${stats.deletions} 行删除` : "",
  ]
    .filter(Boolean)
    .join("\n");

  return { message: body ? `${prefix}\n\n${body}` : prefix };
}
```

### 兜底消息格式示例

```
[auto] (chore): 增量补丁 (基于: a1b2c3d 完成用户登录模块重构)

  3 个文件已变更
  27 行增加
  5 行删除
```

或（无上一次提交时）：

```
[auto] (chore): 初始提交

  5 个文件已变更
  120 行增加
  0 行删除
```

### 变更统计提取

从 diff 中提取变更统计（`extractDiffStats`）的规则：

| 字段 | 来源 | 示例 |
|------|------|------|
| `filesCount` | diff 中 `diff --git` 行数 | `3` |
| `additions` | diff 中 `+` 开头的行数（不含 diff header） | `27` |
| `deletions` | diff 中 `-` 开头的行数（不含 diff header） | `5` |
| `language` | 从文件后缀推断（非必需，可用于未来扩展） | `ts` |

> 统计只对非二进制文本 diff 有效；二进制文件显示为 `[二进制文件]`。

## config.llm 的读取方式（补充）

兜底逻辑的判定依赖于 `config.llm` 的结构。该结构的填充来自 `AppConfig`：

```ts
interface AppConfig {
  apiKey?: string;        // 从 EnvironmentConfig.LLM_API_KEY 读取
  endpoint: string;       // 默认 "https://api.anthropic.com/v1"
  llm: LLMConfig;         // 主模型配置，含 model 字段
}
```

| 字段 | 来源 | 说明 |
|------|------|------|
| `config.llm` | `RepositoryProfile.llm` | `init` 时问答写入，或命令行 `--llm` 传入 |
| `config.llm.model` | 同 `RepositoryProfile.llm.model` | 模型名，空串或缺省表示无模型 |
| `config.apiKey` | `EnvironmentConfig.LLM_API_KEY` | 从环境变量 `LLM_API_KEY` 读取，非存入 `RepositoryConfig` |

> `llm.model` 在 `init` 流程中的读取：用户输入 → `RepositoryConfig.llm` → 写入 `RepositoryProfile`，与生成消息的解耦。

## 边界情况

| 场景 | 行为 |
|------|------|
| diff 为空 | 已在 `executeCommit` 前置校验中返回 `NO_CHANGES`，不会进入兜底 |
| 上一次提交不存在（全新仓库） | 取空串，前缀变为 `[auto] (chore): 初始提交` |
| diff 全部为二进制 | `filesCount > 0` 但 additions/deletions 均为 0，body 只有文件数统计 |
| 仓库无任何提交历史 | 同「全新仓库」 |
| 大模型配置被显式禁用（model = "no-model"） | 触发兜底，行为与未配置一致 |
| init 时用户跳过 LLM 配置 | 触发兜底，同上 |

## 与 F03 的联系

F03（配置能力）中 `config.llm` 的取值来源于 `RepositoryConfig`。若 `RepositoryConfig` 中无 `llm` 字段，则兜底逻辑必须生效。

- F03 中的 `configureLLM()` 将用户选择的模型写入 `RepositoryConfig.llm`；若用户跳过，则不写入 → 导致 F06 中 `config.llm` 为空 → 触发兜底。
- 这一联动保证「用户未配置→自动兜底」的链路完整。
